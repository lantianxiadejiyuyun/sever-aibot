# Linux 服务器 AI 运维平台需求文档

版本：v1.1 · 日期：2026-11-03 · 状态：需求规划

用户在桌面端或手机 App 手动导入 SSH 密钥后，可以查看 Linux 服务器和业务服务的状态，让 AI 进行只读巡检，或确认一份计划，让服务端通过 SSH 执行部署。部署完成后，服务端保存实际验证过的版本、端口、路径等参数。用户换设备或新建会话后，仍能继续管理同一个服务。

## 1. 使用范围与系统分工

首版按单用户管理设计，先用一台测试服务器完成验收。服务器、凭据、会话和部署档案从第一天起按服务器标识关联，添加第二台机器时不混用参数和权限。

| 组成 | 职责 |
| --- | --- |
| 桌面端与手机 App | 登录控制服务端，选择服务器，查看状态、发出指令、确认计划、跟踪任务。两端共用同一份会话和任务记录。 |
| 控制服务端 | 独立于被管理机器部署，提供 HTTPS 接口，保存会话、任务、报告和部署档案，调度采集、巡检及部署。客户端断开不取消已开始的任务。 |
| AI 控制器 | 根据当前目标、用户指令和可用证据选择工具、解释异常或拟定部署计划；不接触私钥，不自行授予执行权限。 |
| SSH 执行器与凭据库 | 执行器核对目标、任务权限和确认记录后，按需取用对应凭据，通过直连或跳板连接 Linux，返回脱敏结果。 |
| 公网探测节点 | 从目标网络之外访问已登记的公网入口。控制服务端位于合适的外部网络时可兼任；否则配置独立节点。探测节点不需要目标机私钥。 |

## 2. 桌面端与手机端

桌面端固定三栏。左侧保留历史会话，底部固定设置；中间默认打开会话；右侧保留 SSH 密钥导入区。切换中间视图不改变当前服务器。

| 位置 | 页面内容与操作 |
| --- | --- |
| 左栏 | 新建、搜索、恢复历史会话；按时间显示标题和关联服务器。底部「设置」管理模型接口、默认模型、上下文预算和巡检策略。 |
| 中栏顶部 | 显示当前服务器、环境、服务、模型和操作模式。可在「AI 会话」「服务器监控」「端口转发」「巡检报告」之间切换。 |
| 端口转发视图 | 内置 gostc-open 的端口转发与 P2P 入口。「端口转发」按当前服务器和服务展示规则；用户可直接管理，也可从规则行进入 AI 会话检查、创建、修改、启停或删除映射。 |
| 中栏会话 | 显示消息、上下文入口、部署计划、确认按钮、执行步骤和验证结果；输入框位于底部。恢复会话时显示原任务状态。 |
| 右栏 | 从本机选择私钥文件，单独输入口令；显示已绑定密钥的名称、指纹、登录用户、直连或跳板配置。支持绑定已有密钥、替换、停用和测试连接。 |
| 手机 App | 按服务器进入监控、AI 会话、端口转发、巡检报告和连接设置；可查看同一条规则、确认转发变更、跟踪任务，也可导入密钥、确认部署及查看异常通知。 |

## 3. SSH 密钥与中转服务

1. **手动导入。** 用户选择 SSH 私钥文件并指定用途。平台不自动扫描设备上的其他密钥。导入、绑定服务器、确认部署是三个独立动作。
2. **凭据保管。** 服务端加密保存私钥及需要托管的口令，解密主密钥与数据库分开存放。私钥、口令和模型 API Key 不回显，不进入提示词、聊天、日志、报告或部署档案。定时巡检使用服务端可取用的受限凭据。
3. **绑定与校验。** 每条连接记录包含服务器、地址、SSH 端口、登录用户、凭据引用及中转方式。首次连接核对主机指纹；指纹变化时暂停连接并提示核实。停用凭据后禁止用它启动新连接。
4. **SSH 中转。** 首版支持直连和已有 SSH 跳板机。跳板机与目标机可使用不同凭据，目标私钥不复制到跳板机。仅能主动出网、没有可用跳板的内网，需另行实现反向连接，不计入首版直连或跳板验收。
5. **模型接口中转。** 在模型设置中单独配置兼容接口地址、模型名称和 API Key。它解决的是控制服务端访问模型的问题，与 SSH 跳板独立配置、独立测试。

## 4. AI 上下文与模型控制

| 控制项 | 要求 |
| --- | --- |
| 目标范围 | 每次工具调用明确绑定服务器、环境及相关服务。切换目标后移除旧目标的运行数据，作废尚未执行的旧计划确认。 |
| 上下文可见 | 「查看上下文」展示本轮使用的资料、来源和采集时间，例如部署档案、最近巡检、会话摘要和脱敏日志。用户可移除可选资料，或固定“本次只检查”等约束。 |
| 长会话 | 依据当前模型的容量预留回复空间。先裁剪无关日志，再摘要早期对话，保留目标、用户约束、已确认计划与未完成任务。界面提示已摘要的范围。 |
| 模型选择 | 设置中测试模型连接、配置容量和工具调用能力；会话顶部可切换模型。切换后保留历史，重新计算上下文预算，每次回答记录所用模型。 |
| 执行权限 | 默认只读巡检，使用受限账号和固定采集动作。部署使用单独授权的账号与动作。模型只能申请调用工具，权限由服务端校验；无工具调用能力的模型只提供分析。日志内容不能成为指令。 |

## 5. AI 部署与服务端记忆

**典型指令：**“把测试机的订单 API 更新到 v1.3。”服务端按下列顺序处理：

1. 读取该服务的部署档案，通过 SSH 核对当前版本、目录和端口。实际状态偏离档案时先展示差异。
2. AI 生成计划，写明目标机器、服务、当前和目标版本、变更步骤、影响、验证方式，以及可用的回退办法。若没有可用回退方式，明确说明。
3. 用户在桌面或手机确认具体计划。执行器只运行该版本的计划；更换目标或修改步骤需要重新确认。首版先支持一种明确的部署方式，建议用 Docker Compose 验证整个流程。
4. 服务端创建唯一任务，记录每一步和脱敏日志。客户端断线、重复点击或模型请求超时时，先查询已有任务，不重复下发部署。
5. 执行后核对实际运行版本、端口和应用健康检查。只有验证通过才更新当前部署档案。若部分步骤已生效、结果无法确认，标记“待核实”，保留上次成功记录和本次现场证据。

**部署档案与会话分开保存。** 每个服务记录服务器和环境、服务名、部署方式、目录与配置路径、版本或镜像摘要、端口映射、健康检查地址、最近验证时间、关联任务和可回退版本。敏感参数只保存凭据引用。每次任务另存历史，删除或清空会话不影响档案。

## 6. 服务器监控与巡检报告

| 监控区域 | 要显示的内容 |
| --- | --- |
| 主机 | SSH 连通性、运行时长、CPU、系统负载、内存、磁盘、网络收发趋势、最后采集时间。无法连接时保留旧值并标注过期，不直接判断宕机。 |
| 服务 | 发现 systemd 服务、Docker 容器和监听端口；用户选定重点监控对象。分开显示进程状态、重启情况和应用健康检查结果。 |
| 公网入口 | 按已登记入口列出协议、地址、转发目标、最近一次外部探测结果、时间和来源；点击进入分层检查。 |
| 最近变化 | 在同一时间线上显示部署、服务重启、转发目标变化、故障及恢复，便于对照。时间接近不能单独证明因果关系。 |

巡检支持**手动、定时和部署后触发**。部署后只检查本次变更的服务及关联入口。每份报告保存服务器、检查时间、触发方式、检查范围、逐项结果、证据、与上次相比的变化、未验证项及下一步建议。定时巡检正常时只留记录；异常出现或恢复时通知手机，同一故障持续期间不重复提醒。

在报告中选择「让 AI 分析此项」，会将该条检查的目标、时间和脱敏证据带入会话。报告是某一时刻的观测记录，不修改部署档案里的预期配置。

## 7. 内置端口转发管理与公网检查

对于面板管理的 gostc 规则，AI 和手动操作共用服务端接口。查询和巡检只读；创建、修改、启停、删除须展示具体映射及影响，用户确认后交由 gostc-open 下发。会话沿用当前服务器、模型和操作权限。任务、巡检报告和服务档案分别记录操作、检查证据及已验证状态。完整流程与验收见[端口转发与 P2P 模块需求](端口转发与P2P需求.md)。

### 宝塔和系统转发的只读检查

端口放行、系统防火墙端口转发及网站反向代理分别展示。仅放行端口不能证明发生转发；内核 NAT 转发也不要求入口端口一定有用户态进程监听。

以登记的映射 **公网 TCP 8443 → 10.0.0.8:443** 为例，一次检查产生四项独立结果：

| 层次 | 检查方法 | 结论边界 |
| --- | --- | --- |
| 宝塔配置 | 识别面板版本和可用的只读规则来源，核对协议、入口、目标地址和目标端口。网站反代另查域名、路径和上游。 | 只有确实读到面板规则才标记“宝塔已配置”；版本未适配、无读取权限时标记“宝塔配置未核实”。 |
| 系统生效规则 | 通过 SSH 读取机器实际启用的防火墙及 NAT 规则，核对是否存在匹配项。 | 单独报告“匹配”“不匹配”或“未核实”。系统中发现规则，不据此断定由宝塔创建。 |
| 转发目标 | 从转发机访问目标地址和端口；若已授权登录目标机，可进一步核对监听进程与应用响应。 | 记录连接被拒绝、超时或实际响应。后端正常不能代替公网验证。 |
| 公网实测 | 从外部节点探测登记的入口。TCP 记录握手结果；HTTPS 使用预期域名、路径及响应特征；UDP 使用相应协议请求。 | 只完成握手则仅标“端口可连”；响应匹配才标“预期业务已验证”。UDP 无响应不能断言端口关闭。无节点则标“公网未验证”。 |

**报告示例：**“宝塔映射匹配；系统规则匹配；从转发机访问后端正常；外部节点连接 8443 超时。公网访问本次未成功，原因待查。”未取得云安全组或上游路由证据时，只把它们列为待查项。巡检只探测已登记入口，不修改宝塔配置或自动放行端口。

参考资料：[宝塔端口规则管理](https://docs.bt.cn/user-guide/security/firewall/port-rule) · [宝塔系统防火墙端口转发示例](https://www.bt.cn/bbs/forum.php?mod=viewthread&tid=50150) · [宝塔网站反向代理](https://docs.bt.cn/user-guide/site/php/site-config/reverse-proxy)。开发时以目标面板实际版本及系统规则为准。

## 8. 实施顺序与验收

先在测试环境打通 SSH 连接和采集，再实现监控、宝塔转发检查及报告，最后接入 AI 部署和档案更新。开始联调前需选定测试机、宝塔版本、一条允许探测的公网映射、外部探测节点，以及一个可部署和回退的测试服务。以下是验收场景，不代表已经执行。

| 场景 | 通过标准 |
| --- | --- |
| 双端与密钥 | 桌面右侧导入并绑定测试密钥，分别验证直连及经跳板连接；手机能查看同一台机器。聊天、日志、报告均无私钥或口令。 |
| 监控断连 | 中断测试机 SSH 后，面板显示无法连接、最后成功时间和过期数据，不把旧指标显示为实时值。 |
| 模型与上下文 | 长会话摘要后仍保留“仅巡检”约束；从测试机切到另一台机器后，原计划无法执行。切换模型不改变账号权限。 |
| 部署与恢复会话 | 手机确认部署后关闭客户端，从桌面重新打开可查看同一任务。重复提交不产生第二次部署；验证成功后，新会话能按档案找到正确服务。 |
| 失败部署 | 部署一个无法通过健康检查的版本，报告保留失败步骤；档案不将失败版本标成已验证。不能确认现场状态时显示“待核实”。 |
| 宝塔转发 | 在一条真实测试规则上验证公网请求能到达预期服务。保留规则并停掉后端后，报告同时显示规则仍在、后端异常、业务验证失败；恢复后记录恢复时间。 |
| 内置转发与 AI | 在当前服务下让 AI 检查一条 gostc 规则，确认修改目标后核对公网响应，再确认删除并核对撤销结果；手机和桌面显示同一任务和规则状态，宝塔检查项不受影响。 |
| 证据缺失 | 移除公网探测节点后显示“公网未验证”；禁用宝塔规则读取权限后显示“宝塔配置未核实”。其他层次仍分别给出能核实的结果。 |
| 巡检报告 | 手动与定时巡检都能生成带时间和证据的报告；部署后只检查相关对象。桌面和手机均可查看报告，并从异常项发起 AI 分析。 |
