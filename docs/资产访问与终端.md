# 资产访问与交互终端

## 已实现路径

资产地址来自服务端登记的资产，不接受浏览器临时填写任意 dial 目标。资产可控制面直连、经一个 Agent 入口、经最多三个 SSH 跳板后连接目标。每个资产必须启用；同一节点不可同时指定 Agent 和 SSH 跳板。跳板必须是 SSH 资产，绑定可用凭据并固定主机指纹。Agent 离线时失败，不回退为控制面直连。

Agent 访问使用独立 `/agent/access` WebSocket，设备 ID 和密钥放在请求头；其二进制数据流承载 yamux。Agent 对控制面发出的登记资产目标调用现有 `relay.Policy.DialContext`，解析和连接使用同一组已验证地址。metadata、未授权 loopback/public 目标会被拒绝。SSH 跳板之后的目标由该跳板的 SSH direct-tcpip 转发，仍只来自登记资产链；入口 Agent policy 约束的是 Agent 实际拨号的第一跳。

`access.RunAgent(ctx, endpoint, deviceID, key, policy)` 运行一次连接，调用方负责重连和退避。控制面设备密钥轮换/删除后调用 `Server.DisconnectAccessDevice(id)` 立即断开流；数据库外部修改另有 5 秒轮询兜底。`Server.CloseAccess()` 必须在停止接收新 HTTP 请求之后、关闭数据库之前调用，会关闭 Agent 流、取消终端并等待终端记录落库。

## 身份与信任

浏览器 API 使用现有登录 cookie。写接口需要 `X-CSRF-Token`；资产检查、指纹发现/确认、凭据测试、创建和连接终端及下载录制还要求有效的二次验证。通过 `/api/v1/auth/step-up` 验证管理员口令。

SSH discovery 仅观察服务器公钥，在 `HostKeyCallback` 返回错误结束握手，不向目标发送密码或私钥认证。访问跳板时仍需要其已固定的指纹及凭据。观察值不自动落为 pin。用户必须通过可信渠道核对 SHA256 指纹，再明确确认；pin 接口重新发现并比对确认值，避免确认旧观察值。后续认证必须匹配固定 pin。资产目标地址、端口、协议或跳板变动会清空该资产 pin；普通资产 CRUD 不允许绕过确认接口写入 pin。

SSH 私钥创建和替换时解析校验。当前接受可直接解析的未加密私钥，不支持导入需要 passphrase 的私钥；私钥默认不可 reveal/export。密码和私钥只从 vault 解密到内存使用。

## 接口

以下路径均相对 `/api/v1`，由 `MountAccess` 挂载（已有 check/test 保留原路由）。

| 方法和路径 | 请求/响应 |
| --- | --- |
| POST `/assets/{id}/check` | `{}`；返回真实 TCP 建连 `{ok,latencyMs,error}`，失败也保存检查记录。目标 SSH 认证是否成功请用凭据 test。 |
| GET `/assets/{id}/checks` | 最近 100 次检查 `{items,total}`。 |
| POST `/assets/{id}/hostkey/discover` | `{}`；返回 `{fingerprint,algorithm}`。 |
| POST `/assets/{id}/hostkey/pin` | `{fingerprint,confirmed:true}`；重新观察并固定，返回观察值。 |
| POST `/credentials/{id}/test` | `{assetId}`；资产必须关联此凭据，进行真实 SSH 认证，成功 `{ok:true}`。不运行命令。 |
| POST `/access/sessions` | `{assetId}`；返回会话对象 `id/assetId/actor/startedAt/endedAt/result/bytesIn/bytesOut`。30 秒内未连接会过期。 |
| GET `/access/sessions` | 最近 200 个终端记录 `{items,total}`。 |
| GET `/access/sessions/{id}/ws` | 同源 WS，必须是创建会话的登录 session。仅允许连接一次。首个文本帧 `{csrf}`，5 秒认证超时。随后二进制帧为终端输入/输出，文本 `{type:"resize",cols,rows}` 调整 PTY，`{type:"close"}` 关闭。 |
| POST `/access/sessions/{id}/terminate` | `{}`；停止活跃会话，记录 `killed`。 |
| GET `/access/sessions/{id}/recording` | 下载 asciinema v2 `.cast`，包含输出及 resize 事件。 |

终端页面 `/terminal/:id` 的 id 是资产 ID。页面使用 xterm 渲染 ANSI/VT、监听尺寸变化，用户点击验证并连接后建立交互 PTY。服务端只调用 SSH Shell，不提供可供自动化任意执行命令的 HTTP 工具。

## 生命周期与录制边界

终端最长 1 小时，15 分钟无输入自动关闭，活跃会话总数最多 32，单次输出最大 16 MiB。WebSocket 消息最大 64 KiB，resize 最大 500 列、200 行。离开页面/断开 WS、登录过期或被撤销、主动终止、Agent 断开都会关闭相应连接。登录撤销每 5 秒检查一次。

录制保存到数据库 `access_recordings`，仅记录远端输出，不单独记录输入。远端 PTY 关闭 echo 的密码输入不会作为输入录制；若远端程序或用户主动打印秘密，它仍会出现在输出录制中。下载及浏览器回放需要登录及二次验证。系统设置支持录制保留期，默认 30 天，允许 1–3650 天；启动及每日清理超期已结束会话的录制，保留访问历史并明确标记过期，录制接口返回 410。进行中的会话不清理。浏览器支持暂停、重播和倍速，只回放已录制输出与 resize，不连接远程设备。数据库备份仍需按组织要求单独管理。每个终端会话记录开始/结束、结果和输入输出字节数；控制面启动后首次访问层初始化把遗留未结束记录标为 interrupted。

生成的 SSH config 仅为本地 OpenSSH 配置参考，不包含密码或私钥。Agent 入口没有公共地址时，配置中的注释不会自动创建本地代理。浏览器终端使用本访问层反向通道；原生 SSH 客户端需要另外配置实际可达入口及本地密钥。

## 验收

`internal/access/access_test.go` 使用本地真实 SSH 服务验证：discovery 不认证/不自动 pin、错误 pin 在认证前拒绝、两级跳板认证成功、私钥解析、真实 Agent 反向通道读 SSH banner、metadata policy 拒绝、离线 Agent 不回退。

`internal/api/access_test.go` 使用本地真实 SSH 会话验证：二次验证、指纹发现路由、WS 首帧 CSRF、PTY、resize、交互输入输出、终止、字节历史与录制下载。测试无需外部机器。这些测试不等于对生产资产或生产网络已完成连通验收。

## 数据源只读访问

数据源页面 `/datasources` 复用同一资产访问通道，仅支持 `mysql` 和 `postgres` 资产。数据源引用资产及其当前绑定的 `db_password` 凭据，凭据必须包含用户名；源资产被禁用或凭据绑定变化时拒绝访问。资产本身可直连、Agent 或 SSH 多跳，MySQL/PostgreSQL 最终数据库协议由真实驱动完成。

`MountDataSources` 提供以下登录接口，除列表外需要有效二次验证；写接口还需 CSRF。

| 接口 | 合同 |
| --- | --- |
| GET/POST `/api/v1/datasources` | 列表 `{items,total}`；创建 `{name,assetId,credentialId,database,tlsMode,enabled}`。 |
| PATCH/DELETE `/api/v1/datasources/{id}` | 更新配置/删除引用，不修改源数据库。 |
| GET `/api/v1/datasources/{id}/schema` | 读取可见表/列结构，结果格式同查询。 |
| POST `/api/v1/datasources/{id}/query` | `{sql}`；返回 `{columns,rows,truncated,durationMs}`。 |

默认 `tlsMode=verify-full`，通过系统信任根校验数据库证书及资产地址对应的名称；不自动降级或跳过证书验证。只有明确设置 `disable` 才关闭数据库 TLS。无自定义 CA 导入界面。

只读约束由服务端 SQL 限制和数据库事务双重执行：仅单条 SELECT，拒绝注释、多语句、WITH、写关键字、用户变量及任意函数，只允许常用聚合/字符串/数值函数。PostgreSQL 使用 `default_transaction_read_only=on` 和 `BEGIN READ ONLY`，MySQL 使用 `START TRANSACTION READ ONLY`。所有请求最终回滚，不提交事务；源库还应使用独立最小权限只读账号，尤其不要给账号超级用户、文件读写、扩展或安全定义者函数权限。SQL 语法限制是保守子集，不能替代源库自身权限管理。

查询 SQL 最多 16 KiB，最多 200 行、100 列、2 MiB 的结果值，超限标记 truncated；额外包裹 LIMIT 201 以识别截断。整体 8 秒超时，数据库语句上限 5 秒，PostgreSQL lock_timeout 为 1 秒，最多 8 个并发数据库请求。MySQL 必须支持 `MAX_EXECUTION_TIME`，不支持的服务器直接失败；当前没有宣称兼容 MariaDB。超时通过关闭底层连接保障 SSH 通道也能取消。审计仅记录数据源 ID、行数、耗时及结果，不记录 SQL、凭据或结果数据。

`internal/datasource/query_test.go` 用本地 PostgreSQL/MySQL 协议服务验证真实驱动握手、只读事务、回滚、超时设置、行数上限和 SQL 拒绝；`internal/api/datasource_test.go` 验证 step-up、CSRF、凭据绑定、TLS 默认和禁用状态。没有配置外部数据库，本次验收未声称对实际 PostgreSQL/MySQL 实例执行 SQL；源库权限、TLS 和兼容性需部署时独立验收。

AI 的 `queryAIDataSource` 复用同一服务端查询边界，额外限制 50 行及单字符串 1000 字节，并按敏感列名、SQL 和值关键词遮盖。关键词不能保证识别未知列名或未知格式中的秘密；调用方仍须校验明确的上下文共享授权和当前二次验证。

## 固定变更提案与部署档案

此模块为手工管理的非生产目标提供固定操作，不替代现有生产部署流程。**当前生产必须使用宝塔 API；宝塔托管目标不得通过此执行器覆盖面板配置。** SSH 执行默认关闭，仅验证环境显式设置 `AIBOT_ENABLE_SSH_CHANGES=1` 才开启；资产须有 `managed:manual` 标签，包含 baota、bt、bt-managed 或 production 标签的目标拒绝执行。

固定允许 nginx/caddy 服务重启，或更新 `/etc/nginx/conf.d/aibot-managed.conf`、`/etc/caddy/Caddyfile`（与服务匹配）。不接受用户命令、脚本、任意路径、包管理或镜像部署。远端需 Linux/systemd、相应服务程序、GNU coreutils 及该 SSH 身份的非交互 sudo 能力；实际命令模板由服务端编译固定，配置正文仅通过 stdin 的 base64 数据传入，不插入 shell 命令。

配置提案创建时只读取得旧文件，生成包含目标、完整替换差异、影响、风险、回滚和验证的快照。快照绑定资产链、固定主机指纹、凭据密文版本和旧配置 SHA256，执行前重新验证。路径本身和父目录不得为符号链接，配置最长 64 KiB。配置可能含可执行指令，因此配置变更始终 high 风险，必须启用 TOTP 并用新验证码批准；恢复码不支持高风险审批。服务重启为 medium 风险，需要二次验证。审批绑定精确 revision、审批人及 5 分钟有效期，数据库原子 claim 防止重放，每个目标同时最多一个变更执行。

批准和执行是不同动作：批准本身不执行。配置审批消费 OTP 后产生绑定快照的一次授权；执行还需当前 step-up、同一审批人、明确确认以及未过期的批准。任何配置内容变化需要新提案。AI 的 `propose_service_restart`、`propose_config_change`、`propose_deploy` 仅生成同类预览（propose_deploy 仅表示固定配置发布）；AI 通用审批完成 CSRF、step-up、高风险 TOTP 和原子 claim 后才进入相同执行引擎，不存在 AI 自动写入路径。

执行先同目录备份，再原子替换配置，运行 nginx -t/caddy validate、固定 systemctl restart、systemctl is-active。失败会恢复旧文件（旧文件不存在则删除新文件），再校验并重启；记录 succeeded/rolled_back/rollback_failed/conflict/failed 等结果。活跃状态验证不代表业务健康；单纯服务重启无法恢复进程内存状态。远端宕机、强制杀死或网络断开不能保证回滚完成，必须人工核验。备份默认保留在远端，当前无自动清理。

| 接口 | 合同 |
| --- | --- |
| GET/POST `/api/v1/changes` | 列表/创建 `{assetId,kind,service,configPath,content,summary}`，kind 为 service_restart/config_update。 |
| GET `/api/v1/changes/capabilities` | 当前执行开关、固定服务、固定配置路径、准入标签。 |
| GET `/api/v1/changes/{id}` | 结构化提案和 revision。 |
| POST `/api/v1/changes/{id}/approve` | `{revision,confirmed:true,otp?}`，high 风险消费 OTP。 |
| POST `/api/v1/changes/{id}/execute` | `{revision,confirmed:true}`，同一审批人单次 claim，返回执行记录。 |
| GET `/api/v1/changes/{id}/executions` | 执行结果、截断到 16 KiB 的输出、远端备份路径和时间。 |
| POST `/api/v1/changes/{id}/archive` | 成功后保存 `{name,version}` 的不可变部署档案。 |
| GET `/api/v1/deployment-archives` | 成功变更的目标、版本、快照摘要及原提案引用，不会自动重新发布。 |

页面 `/changes` 支持创建、差异审阅、人工批准、执行、记录和部署档案；`?proposal=<id>` 可直达审阅。`CloseChanges()` 在关闭数据库之前取消并等待运行记录落库，之后再 `CloseAccess()`；启动时将未结束执行标为 interrupted。

`internal/access/changes_test.go` 经本地真实 SSH 连接，将固定脚本映射到隔离临时目录后实际运行，覆盖成功替换、原始备份、校验失败恢复、外部配置冲突、服务/路径注入拒绝。`internal/store/changes_test.go` 覆盖并发 claim 仅一个成功、过期及已执行审批重放拒绝；API 测试覆盖默认禁执行、step-up、高风险 TOTP 要求及宝塔目标拒绝。未操作用户服务器或执行生产发布。
