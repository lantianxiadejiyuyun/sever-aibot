| AI 转发控制 | 真实模型在测试服务上创建、修改、删除隔离规则；写操作先返回待确认任务，创建前未出现规则，确认后可读回目标端口，删除后从有效规则列表消失。此项验证管理行为。 |
| 转发数据 | 在隔离网络启动真实 gostc 管理端、节点、内网客户端，验证 TCP/UDP 往返、客户端回执、切换目标、停用、启用、删除。转发及 P2P 删除均收到匹配版本的撤销回执；相同时间不同的时区格式正确匹配，旧版本回执保持待撤销。未将回环测试记为公网可达。 |

| 公网探测与规则报告 | 可配置独立的 SSH 巡检主机作为外部探测节点；不可用时保留“未验证”。报告分别记录配置、节点、客户端、应用回执、目标服务和公网证据。后端定向测试通过；尚无第二个实际外部节点的端到端验收结果。 |
| P2P | 授权 visitor 收到目标服务的响应；允许和禁止中继的配置条件均有测试。该结果不能证明不同运营商或两个实际 NAT 之间的 XTCP 直连。 |

此前测试机后端 12 项检查通过。本轮只针对变更及其直接影响执行 9 项后端测试，均通过；真实隧道二进制验收和真实 Docker 验收通过。发布目标为已授权测试机，生产环境未部署。

本轮版本已发布到测试机，42 个运行文件与发布清单的 SHA-256 一致，原环境配置、凭据和数据库保留。首次发布检查使用了错误的健康接口路径，自动恢复原版本；纠正检查路径后重新发布成功。`aibot-web`、`aibot-tunnels` 均正常运行。发布后重新验证了真实 SSH、DeepSeek 巡检、AI 转发增改删、HTTPS 页面与静态资源、未登录接口以及内部管理接口鉴权。面板仍监听 `127.0.0.1:18443`，内部管理端仍监听 `127.0.0.1:18081`。
