# 巡检与通知

当前实现提供持久检查定义、周期调度、手动执行、批次报告、告警和通知投递。页面入口为 `/inspections` 和 `/notifications`，接口位于已认证的 `/api/v1` 下，所有写接口要求现有 CSRF token。

## 检查定义与执行

`GET /checks` 返回 `{items,total}`。`POST /checks` 新建，`PUT /checks/{id}` 完整替换定义，`DELETE /checks/{id}` 删除定义但保留历史报告。运行中的定义不能修改或删除。`POST /checks/{id}/run` 执行一次并返回报告，暂停周期执行的定义仍可手动运行。

公共字段为 `name`、`kind`、`targetKind`、`targetId`、`timeoutMs`、`intervalSeconds`、`enabled`。超时范围为 100–30000 毫秒，周期为 30–86400 秒。调度每 5 秒检查一次到期任务，最多并发 4 个检查；数据库租约防止手动任务和周期任务重叠。结果、告警变化、站内通知和 outbox 在同一事务中落盘。

| kind | 目标 | 附加配置 | 执行语义 |
| --- | --- | --- | --- |
| `tcp` | `asset` / `forward` | 无 | 建立登记路径的 TCP 连接 |
| `http` | `asset` / `forward` | `scheme`、`path` | HTTP GET；仅 2xx 成功，不跟随重定向；响应最大 1 MiB，HTTPS 校验证书 |
| `metric` | `device` | `metric`、`threshold`、`maxAgeSeconds` | 最新设备指标；有 SampleID 使用 CollectedAt 判定新鲜度，legacy 使用接收时间；值大于等于阈值告警 |
| `ssh` | `asset` | `profile` | 固定只读命令，通过已固定指纹的 SSH 访问层执行 |

指标类型为 `cpu`、`memory`、`root_disk`、`load`，分别表示 CPU 使用百分比、已用内存百分比、根分区使用百分比、一分钟负载。百分比阈值范围 `(0,100]`，负载阈值必须大于零。有 SampleID 的新指标按 CollectedAt 判定新鲜度，离线补传旧样本不会因刚接收就触发当前阈值告警；无 SampleID 的 legacy 样本兼容使用 ReceivedAt。证据文本明确区分采样时间和接收时间。`maxAgeSeconds` 范围为 60–3600 秒。缺样、字段不可用、指标过期均为 stale，不按零值或健康处理。

### 探测来源与转发入口

报告 `detail.source` 明确记录执行来源：`control`、`asset-route`、`agent` 或 `ssh`。

- 资产连通检查调用真实资产访问层，遵守 Agent 入口和 SSH 跳板链，不回退为控制面直连。
- port 转发探测节点 `Addr` 的主机和转发 `RemotePort`。
- host 转发连接节点 `Addr` 的主机和 `HTTPPort`，HTTP URL/Host 保留登记的转发域名；配置 `scheme` 应匹配实际入口协议。
- 转发探测来源是 **control（控制面）**，不是外部独立探针，也不证明任何外部运营商网络均可访问。
- 转发必须已 applied/observed。没有公网入口的类型、私有/回环/保留/metadata 地址显示 `unsupported`，归为 stale。DNS 在连接前校验所有返回地址，并使用通过校验的 IP 连接。
- 转发检查从不直接连接其私网 `targetIp:targetPort` 冒充转发成功。

### SSH 固定只读配置

资产必须启用、协议为 SSH、绑定 SSH 凭据并固定主机指纹。访问层验证目标及跳板指纹；凭据不进入报告。API 只接受配置名称，不接受自定义命令或插值参数。

| profile | 固定检查内容 | 判断 |
| --- | --- | --- |
| `system` | `uname -sr`、`uptime`、`df -Pk /`、`cat /proc/meminfo` | 保存系统/磁盘/内存原始只读证据，命令成功表示证据采集成功 |
| `services` | `systemctl --failed --no-legend --plain --no-pager` | 存在失败服务为 down |
| `docker` | `docker ps -a --format '{{.Names}}\t{{.Status}}'` | 存在 unhealthy 或 Exited 容器为 down |
| `firewall` | 优先 `nft list ruleset`，否则 `iptables -S` | 保存规则证据，不作规则合规性判断 |

不自动 sudo，不安装工具，不执行修改命令。工具缺失、权限不足、超时、指纹/凭据失败或证据截断均明确 stale。每个命令 stdout 上限 16 KiB，stderr 不保存；整个 profile 共用检查超时。证据结构为 `name/state/summary/output`。

system/firewall 的 up 仅表示固定证据成功采集，不能解释为资源阈值全部正常或安全策略合规；设备资源告警应使用 metric 检查。

## 结果、评分与批次报告

`GET /inspection-runs` 返回最近 200 次检查，包含名称快照、结论、耗时、时间、上次状态、评分、来源和结构化证据。up=100、down=0、stale=null。页面提供同一检查的历史状态比较、证据查看及 JSON 导出。

`POST /inspection-batches` 接收 `{name,checkIds}`，选择 1–50 个不重复检查；返回 202 和持久批次记录。后台执行不受浏览器关闭影响，单个服务同时运行一个批次，与周期检查共用 4 个执行槽位。批次最长 15 分钟，服务关闭会取消并保存中断结果。

`GET /inspection-batches` 返回最近 100 批次，`GET /inspection-batches/{id}` 返回完整报告。页面提供“运行批次”、检查选择、运行状态、报告详情和 JSON 导出。

批次报告包含：

- `runs`：已完成的检查报告快照及证据。
- `failures`：未完成检查及原因。
- `healthy/failed/stale`：覆盖情况，未验证项单独计数。
- `score`：已验证项中正常项比例乘以 100；全部未验证为 null。
- `previousBatchId/previousScore/scoreDelta`：仅与最近 100 个已完成报告中相同检查 ID 集合的最近批次比较。定义本身后来修改仍保留执行时名称、结论和证据，因此变化应结合定义修改审计理解。

进程崩溃后不会补造成功报告。超过 16 分钟仍 running 的批次由调度恢复逻辑标为 interrupted。报告不是可恢复作业队列，重启后需要重新发起未完成批次。

## 告警与通知

`GET /alerts` 返回告警，`POST /alerts/{id}/ack` 确认，`POST /alerts/{id}/silence` 接收 `{seconds}`，范围 0–604800；0 取消静默。状态恢复会关闭当前事件。静默抑制该事件后续状态变化的新通知，不撤回已经入队或已发送的消息。

`GET /notifications` 返回最近 200 条站内通知，`POST /notifications/{id}/read` 标为已读。站内通知是管理员共享收件箱。

`GET/POST /notify/channels` 查询/新建频道，`PUT/DELETE /notify/channels/{id}` 更新/删除。配置字段为 `name`、`kind`（`feishu` 或 `webhook`）、`enabled` 和写入专用 `webhookUrl`。编辑时 URL 留空保留旧秘密。完整 URL 使用现有 vault 加密保存，因为机器人令牌可能位于 URL 路径。列表和响应不返回 URL、密文或令牌。

回调只支持公网 HTTPS 443，禁止用户名、fragment、内网/回环/metadata 地址。连接时重新解析并校验 DNS，再连接固定 IP；禁止重定向，不使用环境代理。请求最长 10 秒，载荷与响应最大 64 KiB，响应头最大 16 KiB。失败日志只保留脱敏类别、HTTP 状态或飞书结果码。飞书发送 text 消息并验证业务返回码；当前不配置飞书额外签名 secret。

保存频道不会发送测试消息。启用频道后接收后续真实检查状态变化。通用 Webhook JSON 包含 `eventId/checkId/name/state/message/text/createdAt`，并携带 `Idempotency-Key: eventId`。

## Outbox 与运维

`GET /notify/outbox` 查看最近 200 条投递，`GET /notify/logs` 查看最近 200 条尝试日志，`POST /notify/outbox/{id}/retry` 只将最终 failed 的记录重新入队。

每个事件/频道组合唯一。投递使用持久租约，最多尝试 5 次，失败后指数退避；最终失败由管理员手动重试。网络断开或发送成功后进程崩溃可能造成重复投递，远端应按 eventId 去重。飞书机器人没有通用 Webhook 接收端那样的去重保证。

调度与发送 worker 独立运行，慢回调不会阻塞检查排期。启动挂载 `MountOperations` 并调用 `StartOperations(ctx)`；关闭 HTTP 请求后、关闭 store 前调用 `StopOperations()`。测试实例也要调用 StopOperations 释放懒初始化服务。

迁移：`0007_operations.sql` 保存检查、告警、频道和 outbox；`0013_operation_reports.sql` 为检查报告增加 detail 并创建批次报告表。

## 验证

自动化测试使用临时 SQLite、内存连接、本地 HTTP 服务和本地模拟 SSH 服务，不向外部 Webhook 发消息。覆盖状态变化去重、静默恢复、执行租约、重试次数/日志、手动重试、密码学存储与 API 脱敏、HTTP 重定向/大小限制、metadata SSRF、指标过期、SSH 固定命令/指纹/输出限制、转发入口和 Host、批次评分及相同集合历史比较。

运行：`go test ./internal/operations ./internal/store ./internal/api`，前端检查 `npm --prefix web run typecheck`。真实 SSH 权限、飞书群机器人和公网入口可达性需要在部署环境用获授权的资产与频道验证，测试通过不代表已验证外部服务。
