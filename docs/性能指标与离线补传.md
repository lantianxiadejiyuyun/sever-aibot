# 性能指标与离线补传

Agent 每分钟采样，控制面按设备保存最多 1,440 条。性能页提供采样时间范围、历史曲线和可展开的数据表；缺少样本时不补零，连续缺口不会连线。首次 CPU 读数需要基线，因此先显示等待第二次采样。

## 平台支持

| 指标 | Linux | Windows |
|---|---|---|
| CPU 使用率 | 内核累计 CPU 时间差分 | 原生系统时间差分 |
| 物理内存 | 内核内存统计 | 原生内存状态 |
| 1/5/15 分钟负载 | 支持 | unsupported / null |
| 网卡累计收发字节 | 按接口读取 | 按接口读取 |
| 磁盘累计读写字节 | 按块设备读取 | unsupported / null |
| 系统盘容量、已用容量、使用率 | 根文件系统 | 系统卷 |

磁盘父设备与分区的累计 I/O 可能重叠，不能直接相加。累计计数会在设备重启时归零，不等同于瞬时速率。无法读取与平台不支持分别标为 unavailable、unsupported。

## 离线补传

- Agent 内存队列最多 1,440 条、4 MiB；跨连接重建保留，不跨进程重启保留。
- 每批最多 30 条、256 KiB，每条持有稳定样本 ID；收到控制面 ACK 后移除。
- 控制面按设备与样本 ID、采样分钟去重；超出 24 小时的补传样本确认后丢弃，超前超过一分钟的时间戳拒绝。
- 查询窗口、排序、过期状态和指标阈值使用实际采集时间；legacy 单样本回退为接收时间。接收时间独立保留，方便辨别补传延迟。
- 内存容量溢出或 Agent 进程退出可能丢失未送达样本；不承诺持久离线历史。

## 接口

- `GET /api/v1/metrics/overview`：每台登记设备的在线状态、最新样本及是否过期。
- `GET /api/v1/devices/{id}/metrics?hours=24`：按实际采集时间查询，允许 1–168 小时；最大保留条数仍为 1,440，不表示保存完整七天。
- `/api/v1/checks` 的 metric 检查支持 CPU、内存、负载与系统盘使用率。过期或缺失样本为 stale，不会视作健康。

Windows 原生采集、本地真实 Agent → Hub → SQLite 补传、ACK、去重与历史窗口测试已执行；Linux 实现另需在目标 Linux 主机确认具体接口与权限状态。
