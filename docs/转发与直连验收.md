# 转发与直连验收

本文描述 Go 数据面的实际实现。配置被保存、入口已监听、业务已观测、撤销已确认是不同状态，不应合并为“成功”。

## 能力与适用范围

| 类型 | 入口 | 目标协议 | 实际路径 | 适用范围与限制 |
| --- | --- | --- | --- | --- |
| port / TCP | 节点公开 TCP 端口 | TCP | 公开入口 → 节点 → 已认证 Agent 隧道 → 目标 | 入口必须属于节点允许的端口段。 |
| port / UDP | 节点公开 UDP 端口 | UDP | UDP 入口 → 带长度定界的数据报隧道 → Agent UDP socket → UDP 目标 | 保留数据报边界与空数据报，单报文最大 65507 字节。底层 Agent 通道是可靠流，因此具有队头阻塞特性；不等同原生端到端 UDP 网络。 |
| host | 节点 HTTPPort | HTTP over TCP | HTTP Host 路由 → Agent → HTTP 目标 | 支持精确域名和节点允许的通配域名。未知 Host 返回 404。HTTPS 需要前置代理终止 TLS；未提供自动证书签发或原生 HTTPS/SNI 路由。 |
| tunnel / 私有访问 | ClientID 指定的访问设备上的 127.0.0.1:remotePort | TCP | 访问设备 → 已认证节点隧道 → 服务设备 → 目标 | 节点不开公开入口。服务设备与访问设备必须不同。UDP 私有访问未实现。 |
| p2p / direct | 访问设备本机入口；服务设备认证 TCP / QUIC 监听 | TCP | 访问设备 → 服务设备 → 目标 | 支持 TCP 候选直连及自动 UDP NAT 打洞后的 QUIC 直连；需要配置 UDP 会合端点，真实 NAT 兼容性依赖网络。 |
| p2p / relay | 访问设备本机入口 | TCP | 访问设备 → 节点 → 服务设备 → 目标 | 直连失败时，规则和节点同时允许才回退中继。禁止回退或目标无法建立连接则本次业务连接失败，路径报告为 unavailable。 |
| proxy | 访问设备 127.0.0.1:remotePort | HTTP CONNECT / SOCKS5 CONNECT → TCP | 访问设备 → 节点 → 服务设备 → 目标 | 只允许规则指定目标，使用设备票据鉴权；不提供任意目标代理、SOCKS UDP、独立用户名口令或公网监听。成功响应在目标连接就绪后发送。 |
| KCP / QUIC 节点接入 | 节点独立 UDP 端口 | 加密可靠流 | Agent → 节点 TLS 1.3 → ticket/yamux | 已实现。要求可信证书、正确主机名和 UDP 放行，不能经过 HTTP 反向代理。配置见 [NAT 与 UDP 传输](NAT打洞与UDP传输.md)。 |

业务协议由 `options.protocol` 指定，允许 `tcp` 或 `udp`。省略时默认 TCP；错误类型、空字符串和不支持的协议会被拒绝。HTTP、私有访问与 P2P 当前要求 TCP 目标。

## 配置和状态

启动入口为 `POST /api/v1/forwards/{id}/start`，原有 apply 接口仍使用同一启动逻辑。停止入口为 `POST /api/v1/forwards/{id}/stop`。这些路由由 `MountForwardRuntime` 挂在已有认证、CSRF 与权限保护的 API 路由组中。

启动会增加 forward revision，并进入 applying。节点的 bind_result 必须同时匹配所属节点、forward ID 与 revision，才可改变状态。公网规则在监听成功后进入 applied；私有访问和 P2P 在访问设备成功监听本机端口并向节点报告后进入 applied。只有实际复制的业务字节才将当前 revision 标为 observed；控制帧和握手本身不算业务观测。

停止会增加 revision，并进入 stopping。节点关闭公开入口、取消已有中继连接、移除后续访问权限后返回同 revision 的 revoke_result。对于已注册的 P2P 直连服务，节点还要求服务 Agent 关闭直连监听和现有直连连接，并明确回执。只有撤销成功回执才进入 stopped。未确认关闭的直连服务保持 stopping，并显示原因；不能将控制消息已发送当成撤销完成。节点离线时会保留等待状态，重连后重新协调。

从未启动的 saved 规则可以直接停止为 stopped。仅 saved 或 stopped 可以删除。删除保留历史按日流量。编辑和删除使用数据库 revision 条件更新，避免并发请求覆盖更新后的状态。更换节点、服务设备或访问设备前必须完成停止；stopping 期间不允许编辑。旧 bind、旧 revoke 和其他节点的回执不能覆盖当前 revision，也不能把 stopped 恢复为 applied。

`GET /api/v1/forwards/{id}/runtime` 返回状态、revision、节点与服务设备在线状态，以及 P2P 最近连接路径：

- `not_observed`：当前 revision 尚无路径观测。
- `direct`：最近报告的连接采用认证 TCP 或 QUIC 直连。
- `relay`：最近连接在收到目标连接成功确认后采用中继回退。
- `unavailable`：直连失败且禁止回退，或中继建立失败。

这是最近一次连接的路径，并非所有并发连接的统一状态。`automaticNATHolePunching` 表示当前 P2P 规则已配置会合地址且节点限制允许尝试，不代表已经穿透成功。节点还须实际开启 UDP 会合监听。

## P2P 直连配置与身份验证

默认情况下，服务 Agent 在 `0.0.0.0:0` 创建 TLS 监听，并发布本机有效单播 IP 与实际端口。发布和查询候选地址均通过已认证的节点隧道，并校验 forward、revision 与服务/访问设备角色。

可通过高级选项指定明确地址：

```json
{
  "protocol": "tcp",
  "directListen": "0.0.0.0:31001",
  "directAddress": "203.0.113.10:41001"
}
```

该示例要求管理员已将外部 `203.0.113.10:41001` 映射到服务设备的 `31001`。示例中的文档地址不可直接用于生产。`directListen` 与 `directAddress` 使用 IP 地址，不能使用域名。自动候选排除回环、未指定、组播、链路本地和元数据地址；管理员显式配置的回环地址可用于同机测试。

访问设备只信任通过认证通道获得的 TLS 证书指纹。连接要求 TLS 1.3，并通过随机挑战的 HMAC 证明绑定该 forward 和 revision 的密钥。错误证书、错误密钥和旧 revision 不得连接目标。节点配置不携带直连共享密钥，密钥仅投影到相关 Agent 配置。

规则选项 `options.relay` 为布尔值，省略时默认为 true，以兼容已有规则；null、字符串和数字会被拒绝。只有规则允许回退且节点 `P2PDisableForward=false` 才允许中继，访问 Agent 与节点均执行限制。前端 P2P 表单提供独立开关。

TCP 候选查询与 TLS 握手共享 1500ms 预算；配置 UDP 会合后，额外按有界超时尝试 NAT/QUIC。完整时限和兼容性见 [NAT 与 UDP 传输](NAT打洞与UDP传输.md)。回退使用带 revision 的 `@relay:<revision>:<id>` 请求，节点在目标连接就绪后确认；访问 Agent 收到确认才报告 relay。部署时需同步更新节点和 Agent；旧节点不支持该确认协议，不能作为新版 P2P 回退的兼容节点。禁用回退不能使直连凭空成功；对于无法互通的 NAT 环境，业务连接将明确失败。

直连证书是短期证书。当前实现约每 50 分钟重建服务 Agent 到该节点的会话以更新证书和候选，这会关闭该会话上的现有业务连接并触发重连；尚未实现无中断证书轮换。

## 设备密钥轮换与撤销

设备密钥轮换不仅断开控制连接，还写入持久化的隧道撤销 epoch。签名票据携带 IssuedAt；节点在验票以及注册会话的锁内均复核 epoch 和当前签名 secret，避免验票与撤销并发时旧会话重新注册。

相关的活动 forward（服务设备或 ClientID 匹配）在同一撤销事务中 revision 加一。P2P 密钥绑定 revision，因此旧访问设备保留的直连密钥不能继续认证新的服务监听。新的节点配置同步持久化 epoch，节点内 epoch 只增不减；节点重启或重连不能通过遗忘内存撤销记录重新接受旧票据。密钥轮换也会刷新相关服务和访问 Agent 配置，并撤销已有访问反向通道。

票据的 forward 授权范围在节点处理业务流时执行。私有访问另外要求当前设备等于 ClientID；服务设备发布候选则要求设备等于 DeviceID。角色与票据不能互换。

## 节点参数语义

| 参数 | 执行语义 |
| --- | --- |
| ForwardPorts | 公开 port 入口允许的端口和端口段，例如 `20000-21000,22000`。API 校验，节点再次执行。空值表示不限制端口段。 |
| HTTPPort | HTTP Host 路由监听端口；TCP port 规则不能占用该保留端口。 |
| LimiterMbps | 节点中继业务的上下行共享总带宽预算，按实际复制字节执行；0 为不限速。 |
| Concurrency / Connections | 节点活动中继业务连接上限，取两者中较小的正值；两者均为 0 表示不限。UDP 的一个来源地址关联按一个业务连接计。 |
| MaxPoolCount | 节点同时维护的已认证 Agent 隧道会话池上限；同一设备替换自己的会话不额外占用名额，0 表示不限。 |
| AllowWildcard / Domain / DenyDomainPrefix | HTTP 域名的通配许可、后缀和禁用前缀校验。相同节点不能配置相同域名。 |
| P2PDisableForward | P2P 禁止中继回退；不禁止经过认证的真实 TCP 直连。 |

访问设备的私有入口由操作系统绑定，因此不同节点的规则也不能在同一设备重复占用同一本机端口；API 会检查现有规则，Agent 仍以实际 bind 结果为准。

节点带宽、活动连接和流量额度适用于经过节点的业务流。启用任一相关限制后，节点和 Agent 禁止直连，使用允许的中继；禁止中继时明确不可用，不能绕过限制。`LimitTotalGB`、`LimitKind`、`LimitResetDay` 已实施持久、原子的写入前额度预留，详见 [流量额度](流量额度.md)。失败写入不退还预留，历史用量不回填；实际成功流量报告与预留额度分开展示。自定义 `Rules` 仍只是备注文本，没有任意规则语言执行器。

## 流量接口与计量边界

- 单规则：`GET /api/v1/forwards/{id}/traffic?days=30`。
- 全部规则日汇总：`GET /api/v1/traffic?days=7`。
- days 范围为 1–366；响应包含 `items`、`timezone: "UTC"`、`uploadDirection: "public_to_target"`、`downloadDirection: "target_to_public"`。
- 每项为 `{ "day": "YYYY-MM-DD", "uploadBytes": 0, "downloadBytes": 0 }`。只返回有样本的日期；空集合表示没有样本，不生成演示流量。

上行表示公开入口或私有访问设备到目标，下行表示目标到入口。节点中继记录成功复制的业务字节；直连由授权访问 Agent 采集业务字节，再通过认证通道提交给节点。TLS、yamux 和 UDP 定界头等隧道开销不计入；HTTP 应用头部属于转发的应用字节。

长连接每秒上报增量，因此不必等连接结束才观测业务。按 UTC 日期聚合的边界存在约一秒采样误差，不能作为高精度结算账本。节点保存尚未被控制面确认的报告，重连重发；数据库以节点和 report ID 去重，避免重复累计。控制面仅接受所属节点的报告。

当前待确认队列位于节点进程内存中，并非持久化日志。节点崩溃、进程重启，以及直连 Agent 到节点的报告尚未传递时，未确认样本可能丢失。自动恢复不等同零丢失计费。报告接收时限制时间范围，超过七天的历史重放不予接受。

## 可重复验收

1. **TCP / WS 中继**：启动节点、服务 Agent 与 TCP echo 目标，创建并启动 port。确认 applied 后发送业务数据，保持连接未关闭时也应出现 observed 和非零双向流量。分别使用原始 TCP 和 WebSocket Agent 通道重复。
2. **UDP**：目标使用真实 UDP echo socket，配置 `options.protocol=udp`。测试多报文边界、60000 字节报文和空数据报，均应原样返回；不能使用 TCP echo 目标代替验收。
3. **HTTP Host**：配置节点 HTTPPort 和目标 HTTP 服务。正确 Host 返回目标响应；未知 Host 返回 404；校验不允许的域名后缀、前缀、通配设置与端口冲突。
4. **私有访问**：启动不同身份的服务 Agent 与访问 Agent，配置 DeviceID、ClientID 和访问设备本机端口。仅访问设备的 127.0.0.1 入口可用，节点不新增该公开端口；不具备票据范围或 ClientID 不匹配的设备不能转接。
5. **真实直连**：服务设备配置可达的 directListen/directAddress，并开启 P2PDisableForward。访问设备连接成功、目标返回业务数据，runtime 必须报告 direct。禁回退且仍能成功，证明未借中继掩盖直连失败。
6. **回退与拒绝回退**：将 directAddress 指向不可达端口。规则和节点均允许时业务成功且报告 relay；分别单独禁止规则回退或节点回退，业务必须失败并报告 unavailable。允许回退但目标不可连接时也应报告 unavailable；直接调用节点回退协议不能绕过任一限制。
7. **直连鉴权**：错误 TLS 指纹、错误 HMAC 密钥或旧 revision 均不能进入目标连接。候选地址中的元数据、组播、链路本地、无端口或域名形式应被拒绝。
8. **停止与旧回执**：保留正在传输的连接后停止，等待 matching revision 的撤销回执。已有连接必须关闭，stopped 后不能重新建立该业务访问。重放旧 bind 或其他节点的回执不能复活规则。直连服务不能确认关闭时保持 stopping。
9. **密钥轮换**：保留访问设备旧 P2PKey 和旧 revision，轮换设备 key。已有业务连接关闭，相关 forward revision 增加，服务设备使用新密钥重新发布；新凭据可连，旧凭据即使接受新证书也不能认证。
10. **策略和并发修改**：端口池外的入口由节点拒绝；带宽预算实际延迟数据复制；并发上限拒绝额外连接。与 stop 并发的旧 revision 编辑和删除均应失败。

相关自动测试位于 `internal/node/relay_test.go`、`internal/node/runtime_policy_test.go`、`internal/tunnel/direct_test.go` 与 `internal/store/forwards_runtime_test.go`。测试包含真实 Agent、真实 TCP/UDP/HTTP 目标、双 Agent 私有访问、direct/fallback、直连旧密钥撤销、持续连接观测、回执版本隔离和流量去重。跨真实 NAT、防火墙和运营商网络的外部环境仍需按上述边界单独验收，不能由本机测试推断自动 NAT 穿透能力。
